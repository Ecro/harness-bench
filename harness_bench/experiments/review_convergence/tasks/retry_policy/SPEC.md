# SPEC — RetryPolicy (지수 백오프 + 지터 + 서킷 브레이커)

> **이 문서는 계약입니다.** 구현자·리뷰어·수정자 모두 이 문서를 받습니다.
> 인수 테스트는 **이 문서만 보고, 구현이 존재하기 전에** 작성되었고, 구현을 본 뒤에는
> 수정하지 않습니다. 따라서 인수 테스트 실패 = **여기 적힌 계약을 못 지킨 것**입니다.

## 1. 개요

호출 실패 시 지수 백오프로 재시도하고, 연속 실패가 임계치를 넘으면 회로를 열어 호출 자체를
차단하는 정책 객체.

시간과 난수는 **주입**받는다. 실제로 잠들거나 실제 난수를 쓰면 안 된다.

## 2. 인터페이스

```python
class CircuitOpenError(Exception):
    """회로가 열려 있어 호출이 차단됨."""


class RetryPolicy:
    def __init__(
        self,
        max_attempts: int,        # 최초 호출 포함 총 시도 횟수 (>= 1)
        base_delay: float,        # 첫 재시도 전 기본 지연(초)
        max_delay: float,         # 지연 상한(초)
        retryable: tuple,         # 재시도 대상 예외 타입들
        failure_threshold: int,   # 회로를 여는 연속 실패 call 수 (>= 1)
        cooldown: float,          # 회로가 열린 뒤 half-open 까지 대기(초)
        time_fn,                  # () -> float, 현재 시각(초, 단조증가)
        sleep_fn,                 # (float) -> None, 지연
        rand_fn,                  # () -> float, [0.0, 1.0) 균등난수
    ): ...

    def call(self, fn, *args, **kwargs): ...

    @property
    def state(self) -> str: ...   # "closed" | "open" | "half_open"
```

`call()` 은 `fn(*args, **kwargs)` 의 반환값을 그대로 돌려주거나 예외를 전파한다.

## 3. 인수 조건

### 재시도

**AC-01 — 성공하면 한 번만 호출한다.**
`fn` 이 첫 호출에서 성공하면 `fn` 은 정확히 1회 호출되고, `sleep_fn` 은 호출되지 않는다.

**AC-02 — `max_attempts` 는 최초 호출을 포함한 총 시도 횟수다.**
`max_attempts=3` 이고 `fn` 이 항상 재시도 대상 예외를 던지면, `fn` 은 정확히 **3회** 호출된다.
(최초 1회 + 재시도 2회)

**AC-03 — 모든 시도가 실패하면 마지막 예외를 전파한다.**
`max_attempts` 를 모두 소진하면 **마지막 시도**가 던진 예외 객체가 그대로 전파된다.

**AC-04 — 마지막 시도 뒤에는 잠들지 않는다.**
`max_attempts=3` 이고 전부 실패하면 `sleep_fn` 은 정확히 **2회** 호출된다.
(시도 사이에만 잠들며, 마지막 실패 뒤에는 잠들지 않는다)

**AC-05 — 재시도 대상이 아닌 예외는 즉시 전파한다.**
`retryable` 에 속하지 않는 예외가 발생하면 재시도하지 않고 즉시 전파하며, `sleep_fn` 은
호출되지 않는다. `fn` 은 1회만 호출된다.

### 백오프와 지터

**AC-06 — 지연은 지수적으로 증가하고 상한에서 잘린다.**
`k` 번째 재시도 직전의 **상한 적용 후 기준 지연**은
`min(base_delay * 2 ** (k - 1), max_delay)` 이다. (`k` 는 1부터 센다)

**AC-07 — 지터는 상한 적용 *뒤에* full jitter 로 적용한다.**
실제로 `sleep_fn` 에 전달되는 값은 `rand_fn() * (AC-06 의 기준 지연)` 이다.
즉 `[0, 기준지연)` 구간의 균등 분포이며, **상한을 적용한 뒤** 지터를 곱한다.

> AC-06 과 AC-07 의 순서가 중요하다. 지터를 먼저 곱하고 상한을 적용하면 분포가 달라진다.

**AC-08 — 상한은 실제로 잘린다.**
`base_delay=1.0, max_delay=5.0` 일 때 4번째 재시도의 기준 지연은 `min(8.0, 5.0) = 5.0` 이다.

### 서킷 브레이커

**AC-09 — 브레이커는 attempt 가 아니라 call 단위로 센다.**
`call()` 한 번이 내부적으로 3회 시도해서 최종 실패했다면, 연속 실패 카운터는 **1** 만 증가한다.

**AC-10 — 연속 실패가 임계치에 도달하면 회로가 열린다.**
`failure_threshold=2` 일 때, 실패하는 `call()` 이 2번 일어나면 `state == "open"` 이 된다.

**AC-11 — 열린 회로는 즉시 차단한다.**
`state == "open"` 인 동안 `call()` 은 `fn` 을 **호출하지 않고** `CircuitOpenError` 를 던진다.
`sleep_fn` 도 호출하지 않는다.

**AC-12 — 성공하면 연속 실패 카운터가 0으로 리셋된다.**
`failure_threshold=3` 일 때 실패 2회 → 성공 1회 → 실패 2회 순서로 호출하면 회로는 열리지 않는다.

**AC-13 — cooldown 이 지나면 half-open 으로 전이한다.**
회로가 열린 시각으로부터 `cooldown` 초 **이상** 경과한 뒤 첫 `call()` 은 `fn` 을 실제로
호출하며, 그 호출 시점의 `state` 는 `"half_open"` 이다.

**AC-14 — half-open 에서 성공하면 닫힌다.**
half-open 상태의 시험 호출이 성공하면 `state == "closed"` 가 되고 연속 실패 카운터는 0 이다.

**AC-15 — half-open 에서 실패하면 다시 열리고 cooldown 이 재시작된다.**
half-open 시험 호출이 실패하면 `state == "open"` 이 되며, cooldown 은 **그 실패 시점**부터
다시 센다.

**AC-16 — half-open 에서는 시험 호출이 하나만 허용된다.**
half-open 상태에서 시험 호출이 진행 중일 때 들어온 다른 `call()` 은 `CircuitOpenError` 를
던진다. (`fn` 미호출)

**AC-17 — 재시도 대상이 아닌 예외도 브레이커에는 실패로 센다.**
AC-05 에 따라 즉시 전파되더라도, 그 `call()` 은 연속 실패 카운터를 1 증가시킨다.

**AC-18 — `CircuitOpenError` 자체는 실패로 세지 않는다.**
회로가 열려 차단된 `call()` 은 연속 실패 카운터를 증가시키지 않는다.
(안 그러면 열린 회로가 영원히 자기 자신을 갱신한다)

### 입력 검증

**AC-19 — 잘못된 설정은 생성 시점에 거부한다.**
`max_attempts < 1`, `failure_threshold < 1`, `base_delay < 0`, `max_delay < base_delay`,
`cooldown < 0` 중 하나라도 해당하면 `__init__` 에서 `ValueError` 를 던진다.

## 4. 명시적 비목표

- 스레드 안전성은 요구하지 않는다. AC-16 은 단일 스레드에서 재진입으로 검증 가능하다.
- 비동기(`async`)는 다루지 않는다.
- 로깅, 메트릭, 관측성은 요구하지 않는다.
- 지터의 통계적 분포 검정은 요구하지 않는다. `rand_fn` 이 주입되므로 결정적으로 검증한다.

## 5. 구현 제약

- 표준 라이브러리만 사용한다.
- 단일 파일 `retry_policy.py` 로 구현한다.
- `time.sleep`, `random`, `time.monotonic` 을 직접 부르지 않는다 — 주입된 것만 쓴다.
