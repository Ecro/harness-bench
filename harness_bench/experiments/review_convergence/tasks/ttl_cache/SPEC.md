# SPEC — TtlCache (용량 제한 LRU + TTL)

> **이 문서는 계약입니다.** 구현자·리뷰어·수정자 모두 이 문서를 받습니다.
> 인수 테스트는 **이 문서만 보고, 구현이 존재하기 전에** 작성되었고, 구현을 본 뒤에는
> 수정하지 않습니다. 따라서 인수 테스트 실패 = **여기 적힌 계약을 못 지킨 것**입니다.

## 1. 개요

키-값을 보관하되 **개수 상한**과 **수명(TTL)** 을 갖는 캐시. 상한을 넘으면 가장 오래
쓰이지 않은 항목부터 버린다.

시간은 **주입**받는다. 실제 시계를 직접 읽으면 안 된다.

## 2. 인터페이스

```python
class TtlCache:
    def __init__(
        self,
        capacity: int,   # 보관 가능한 최대 항목 수 (>= 1)
        ttl: float,      # 항목 수명(초) (> 0)
        time_fn,         # () -> float, 현재 시각(초, 단조증가)
    ): ...

    def get(self, key): ...          # 값을 돌려주거나 KeyError
    def put(self, key, value): ...   # None
    def __len__(self): ...           # int
```

## 3. 인수 조건

**AC-01 — 넣은 것은 꺼낼 수 있다.**
`put(k, v)` 직후 `get(k)` 는 `v` 를 돌려준다.

**AC-02 — 없는 키는 `KeyError`.**
한 번도 넣지 않은 키를 `get` 하면 `KeyError` 를 던진다.

**AC-03 — 개수 상한을 넘지 않는다.**
`capacity` 개를 초과해 보관하지 않는다. `capacity=2` 일 때 서로 다른 키 3개를 넣으면
그중 하나는 더 이상 `get` 되지 않는다.

**AC-04 — 상한 초과 시 가장 오래 쓰이지 않은 것부터 버린다.**
`capacity=2` 에서 `put(a) put(b) put(c)` 순서면 버려지는 것은 `a` 다.

**AC-05 — `get` 도 "쓴 것"으로 센다.**
`capacity=2` 에서 `put(a) put(b) get(a) put(c)` 면 버려지는 것은 `b` 다.

**AC-06 — TTL 이 지난 항목은 돌려주지 않는다.**
`put(k, v)` 후 시각이 `ttl` 을 **초과해** 흐르면 `get(k)` 는 `KeyError` 를 던진다.

**AC-07 — 같은 키에 다시 넣으면 값이 바뀐다.**
`put(k, v1)` 후 `put(k, v2)` 하면 `get(k)` 는 `v2` 다. 항목 수는 늘지 않는다.

**AC-08 — 잘못된 설정은 생성 시점에 거부한다.**
`capacity < 1` 또는 `ttl <= 0` 이면 `__init__` 에서 `ValueError` 를 던진다.

## 4. 명시적 비목표

- 스레드 안전성은 요구하지 않는다.
- 비동기(`async`)는 다루지 않는다.
- 통계·메트릭·로깅은 요구하지 않는다.
- 만료 항목을 배경에서 청소하는 별도 스레드/타이머는 요구하지 않는다.

## 5. 구현 제약

- 표준 라이브러리만 사용한다.
- 단일 파일 `ttl_cache.py` 로 구현한다.
- `time.time` / `time.monotonic` 을 직접 부르지 않는다 — 주입된 것만 쓴다.
