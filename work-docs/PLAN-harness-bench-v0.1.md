# PLAN — harness-bench v0.1

**한 줄**: LLM 하네스 실험을 재현 가능하게 돌리는 오픈 **코어 + 실험 모음**.
새 모델이 나오면 `bench run --model X` 한 번으로 기존 모델과 같은 표에 얹고,
**그 모델을 어떻게 운용해야 하는지 처방까지 산출한다.**

첫 실험은 코드리뷰 수렴이지만 **코어는 리뷰를 모른다.**

## 0. 왜 만드는가

spoton 에서 400여 회 LLM 호출로 11개 실험을 돌렸고, **결론이 스무 번 뒤집혔다.**
그 중 상당수는 코드가 아니라 **측정 조건**이 만든 것이었다 — 격리 실패, 프로브 고장,
스크래치 위치, 프롬프트 교란. 그래서 이 레포의 1차 산출물은 도구가 아니라 **규율**이다.

새 모델이 나올 때마다 같은 조건에서 다시 재려면 조건이 **코드로 동결**돼 있어야 한다.

## 1. ADR — 되돌리기 어려운 결정

### ADR-001 — 벤치마크(A)를 먼저, 툴킷(B)은 후행

두 물건이 섞여 있었다.

```
A  벤치마크   "새 모델을 기존과 비교"   완전 자동 · 판정 불필요 · 숫자로 떨어짐
B  툴킷      "남이 자기 리포에 적용"   대상·오라클 교체 가능해야 함
```

**A 채택.** 근거 셋:
1. 요청된 use case 가 A 다 (*"새 모델이 나오면 이어서"*).
2. **A 는 사람 판정이 필요 없다.** Python 과제는 계약이 오라클이라 개입할 자리가 없다.
   원 연구의 최대 약점(판정자=저자 64건)이 A 에는 **구조적으로 부재**한다.
3. B 를 먼저 하면 인터페이스를 추상화하느라 A 의 조건 동결이 늦어진다.

**Rejected alternatives**
- *B 먼저* — 범용성이 먼저 서면 벤치가 안 굳는다. 벤치는 조건이 안 움직여야 값이 있다.
- *둘 동시* — 첫 릴리스에 추상화 부채를 지고 시작한다.

### ADR-001b — 코어와 실험을 분리한다. 경계 규칙은 한 줄이다

이 레포는 리뷰 실험만 담지 않는다. 앞으로 다른 하네스 실험(계획·명세·수정·검증 단계 등)이
들어온다. 지금 분리해두지 않으면 두 번째 실험이 들어올 때 리뷰 전용 가정이 코어에 박혀 있다.

> **경계 규칙: 코어는 "어떻게 재는가" 를 알고 "무엇을 재는가" 는 모른다.**
> `core/` 는 `experiments/` 를 **import 할 수 없다.** 테스트로 강제한다.

```
harness_bench/
  core/                     ← 실험 무관. 리뷰라는 단어가 나오면 안 된다
    sandbox/    격리 + 양방향 카나리 프레임워크 (POS/NEG 대조가 코어 계약)
    runner/     모델 어댑터 · 재시도 금지 · 토큰 회계 · CallResult
    cluster/    provenance-blind 클러스터링 + ARI 게이트
    prereg/     예측 동결 · exploratory 낙인
    stats/      전수 조합 커버리지 · 귀무분포 · Fisher · 뮤테이션 · 차등 재생
    ledger/     결과 축적 · 모델 프로파일 스키마
  experiments/
    review_convergence/     ← 지금 것 전부가 여기로
      tasks/ prompts/ oracle/ metrics/ prereg.yaml traits.yaml
    <다음 실험>/
  profiles/                 모델 프로파일 + 처방 (ADR-001c)
```

**실험이 코어에 요구할 수 있는 것은 인터페이스 5개뿐이다**: 과제 · 프롬프트 · 오라클 ·
지표 · 사전등록. 그 밖의 것이 필요하면 **코어가 부족한 것이지 예외를 둘 자리가 아니다.**

애매한 것들의 귀속을 미리 정한다 (나중에 논쟁하지 않기 위해):

| | 귀속 | 이유 |
|---|---|---|
| 차등 테스트 재생기 | **core** | "시나리오를 두 판본에 재생해 트레이스 비교" 는 도메인 무관 |
| 300개 시나리오 자체 | experiment | 과제의 입력 공간이다 |
| 뮤테이션 엔진 | **core** | 섭동 → 스위트가 죽이는가. 도메인 무관 |
| Cognitive Complexity | **core** (언어별 플러그인) | 측정 도구 |
| 카테고리 팬아웃 | experiment | 리뷰의 축이다. 다른 실험은 다른 축을 쓴다 |
| 정밀도/재현율 대 판정 | experiment | 판정 개념이 리뷰 고유 |
| 커버리지 전수 조합 | **core** | "k개 뽑아 합집합" 은 순수 조합론 |

**Rejected alternatives**
- *지금은 한 실험이니 나중에 분리* — 두 번째 실험이 들어오는 시점이 가장 바쁜 시점이다.
  그때 리팩터링하면 첫 실험의 결과 재현성이 깨진다(ADR-008 과 충돌).
- *플러그인 레지스트리로 완전 추상화* — 실험이 하나뿐인데 추상화가 앞서면 잘못된 이음매가 굳는다.
  **import 금지 한 줄**만 강제하고 나머지는 두 번째 실험이 알려주게 둔다.

### ADR-001c — 산출물은 점수가 아니라 **모델 프로파일 + 처방**이다

*"새 모델이 나오면 어떻게 운용해야 하는지도 유추할 수 있어야 한다"* 는 요구.
**유추를 사람에게 맡기지 않고 산출물로 만든다.**

원 연구에서 실제로 이런 대응이 나왔다.

```
측정한 특성                              →  결정되는 하네스 손잡이
────────────────────────────────────────────────────────────────
변동폭 (같은 코드 N회 지적 수 분포)         →  몇 회 돌려야 하는가
루프 감쇠 (지적이 라운드마다 주는가)         →  라운드 상한이 필요한가
churn 방향 (마르는가 / 증가하는가)          →  churn 을 정지기준으로 쓸 수 있는가
콜당 진짜 발견                            →  예산 배분 · 혼합 비율
리포 접근 시 말수 방향 (아낌 / 늚)          →  사람 선별 부담 · 팬아웃 필요성
거부율                                    →  수정자로 쓸 수 있는가
malformed 율                             →  JSON 강제를 믿을 수 있는가
도구 차단 가능 여부                        →  동등 조건에 놓을 수 있는가 (미해결)
```

실제로 갈렸던 예:

```
claude   말 아낌(−51%) · churn 안 마름 · 콜당 1.40  →  팬아웃 필요 · 상한 필수 · churn 게이트 금지
codex    말 늚(+37%)  · 3R 에 마름   · 콜당 2.70  →  단독 충분 · 상한 덜 중요 · churn 게이트 작동
```

따라서 `bench run` 의 산출은 셋이다.

```
1  raw          모든 호출·응답·토큰·시각
2  profile      위 표의 특성값 (모델당 한 행)
3  prescription 특성 → 손잡이 매핑을 적용한 운용 처방 (근거 등급 포함)
```

**3번은 규칙 기반이고 규칙은 실험이 소유한다** (`traits.yaml`). 코어는 스키마와 렌더만
제공한다 — 그래야 다음 실험이 자기 특성표를 들고 들어올 수 있다.

⚠️ **처방은 측정보다 약하다.** 특성→손잡이 매핑 자체가 이 연구의 [판단]인 경우가 있으므로
각 처방 줄에 근거 등급(★★★ 두 모델 재현 / ★★ 단일 / ★ 판단)을 **반드시 병기**한다.
등급 없는 처방은 렌더하지 않는다.

### ADR-002 — 전 과제·전 데이터 공개 (C 펌웨어 판정 시트 포함)

founder 결정. 내가 제기한 우려는 **판정 시트가 사실상 SpotOn 펌웨어의 결함 목록**이라는
것이었다(D01 랩 산술 · D05 TOCTOU · D11 진단 불가 등). 재확인받고 진행한다.

정당화가 성립하는 근거: **자기 제품의 결함이고 제3자 피해가 없으며**, SpotOn 은 Phase 3 에
오픈소스가 예정돼 있어 방향이 일관된다. 그리고 공개하지 않으면 이 연구의 6부(오탐 분석)를
**아무도 검증할 수 없다** — 그게 이 벤치마크의 신뢰성에 더 큰 비용이다.

**단, C 펌웨어 과제는 벤치마크 본편이 아니라 `case-studies/` 로 간다** (ADR-005).

**Rejected alternatives**
- *판정 시트만 비공개* — 6부가 인용 불가가 된다. 공개의 목적이 사라진다.
- *결함을 익명화* — 파일·행 번호가 근거의 전부다. 익명화하면 검증 불가.

### ADR-003 — 라이선스 이원화: 코드 Apache-2.0 / 데이터·프롬프트 CC-BY-4.0

- **코드 Apache-2.0** — MIT 가 아니라 Apache 인 이유는 **특허 조항**이다. 남이 이 하네스를
  제품에 넣을 때 방어가 된다. 벤치마크는 인용·포크가 목적이므로 마찰을 줄여야 한다.
- **데이터·프롬프트·결과 CC-BY-4.0** — 프롬프트와 판정 시트는 코드가 아니라 저작물이다.
  귀속만 요구하고 재사용은 열어둔다. 인용될 때 출처가 남아야 결과가 추적된다.

`LICENSE`(Apache) + `LICENSE-DATA`(CC-BY) + `NOTICE` 에 경계를 명시한다.

**Rejected alternatives**
- *전부 MIT* — 특허 방어 없음. 벤치는 오래 살아야 하는 물건이다.
- *전부 CC-BY* — 코드 라이선스로 부적합(면책·기여 조항 없음).

### ADR-004 — 토큰 기록은 v0.1 릴리스 블로커

원 연구는 토큰을 안 쟀다. 콜 수·벽시계·응답 바이트가 대리변수였는데,
**입력(코드 + 누적 지적)이 라운드마다 커지므로 실제 비용은 그보다 가파르게 오른다.**

이 벤치마크의 핵심 축이 **비용 대비 품질**인데 비용 축이 대리변수면 축이 없는 것과 같다.
따라서 `usage.input_tokens / output_tokens / cached` 를 CallResult 에 넣고,
**얻지 못하면 그 실행을 `degraded` 로 표시**한다(조용히 0 으로 두지 않는다).

### ADR-005 — 과제는 티어로 나눈다

```
tier-1 (bench)         retry-policy · ttl-cache      pytest 만. 의존성 0. CI 에서 돈다
tier-2 (case-studies)  c-firmware (swing_capture)    Zephyr/west 필요. 재현 선택
```

**tier-1 만이 모델 비교의 근거**다. tier-2 는 공개하되 *"우리가 이렇게 했다"* 의 기록이지
*"당신도 돌려라"* 가 아니다. 티어를 안 나누면 남이 Zephyr 를 못 깔아서 벤치 전체를 포기한다.

### ADR-006 — 규율은 문서가 아니라 코드로 강제한다

원 연구의 뒤집힘 스무 번 중 상당수가 규율 위반이 아니라 **규율을 코드가 안 지켜서** 났다.
따라서 다음은 런타임 게이트로 만든다. 위반 시 **수치 산출을 거부**한다.

| 규율 | 강제 방식 |
|---|---|
| 양방향 카나리 | 카나리 미통과면 러너가 실행 자체를 거부 |
| 재시도 금지 | 러너에 retry 파라미터를 두지 않는다. 실패는 기록만 |
| ARI 게이트 | 클러스터 ARI < 임계면 분석이 수치 대신 `UNQUOTABLE` 반환 |
| 프롬프트 무결성 | 프롬프트 SHA 를 결과에 박고, 파생 프롬프트는 diff 게이트로 생성 |
| 사전등록 | `prereg.yaml` 없으면 `--exploratory` 플래그를 강제, 결과에 낙인 |

### ADR-007 — 시크릿은 3중 방어

러너가 실제 자격증명을 스크래치 HOME 으로 복사한다. **한 번 커밋되면 되돌릴 수 없다.**

1. `.gitignore` 최상단 블록 (완화 금지 주석 포함)
2. `pre-commit` 훅 — 경로 패턴 + 내용 스캔(`sk-…` / `access_token`)
3. CI 시크릿 스캔

**설치 즉시 양성 대조로 검증했다** — 가짜 토큰을 커밋 시도해 훅이 실제로 차단하는 것을
확인했다. *"막혔다"는 증명이 아니다* 라는 이 연구 자신의 교훈을 적용한 것이다.

### ADR-008 — 기존 결과 재현이 Phase 1b 의 종료 조건

이식하면서 조용히 조건이 바뀌는 것이 가장 위험하다. 원 연구의 저장된 응답을 **그대로 재분석**해
같은 수치가 나오는지 대조한다. 안 맞으면 이식이 실패한 것이다.

코어(Phase 1)에는 이 게이트를 걸 수 없다 — 코어만으로는 산출할 수치가 없기 때문이다.
그래서 게이트는 **Phase 1b** 에 있고, 코어는 자체 단위테스트로만 검증한다.
**LLM 을 한 번도 부르지 않고 통과해야 한다** (저장된 응답 재분석이므로).

## 2. 구현 계획

### Phase 1 — 코어 추출 (실험 무관 부분만)

**범위 in**: `core/` 6개 모듈. ADR-001b 귀속표에서 **core** 로 표시된 것만.
**범위 out**: 리뷰 프롬프트·과제·오라클(Phase 1b) · tier-2 · CLI · 문서

- 경계 테스트: `core` 가 `experiments` 를 import 하면 **실패**. `grep -ri review core/` 도 0건.

- 경로 이식: `/home/noel` 하드코딩 15개 파일 → 설정
- 스크래치 기본 루트를 **`/tmp` 밖**으로 (codex 헬퍼 생성 거부 이슈 — 이 연구가 3번 오진단한 것)
- **종료 조건**: 경계 테스트 통과 + 코어 단위테스트 (뮤테이션으로 판별력 확인)

### Phase 1b — 첫 실험 이식 (`experiments/review_convergence/`)

tier-1 과제 2종 + 검증된 오라클 + 리뷰/수정 프롬프트 + 리뷰 고유 지표 + `traits.yaml`.

- 스크래치 기본 루트를 **`/tmp` 밖**으로 (codex 헬퍼 생성 거부 — 이 연구가 3번 오진단한 것)
- **종료 조건 (ADR-008)**: 원 연구 저장 응답을 새 코드로 재분석해
  `실험2 §변동폭`·`E1 자유공간 104/120`·`예산표 k=1..6` 이 **소수점까지 일치**

### Phase 2 — 벤치 인터페이스

```
bench canary  --model X                     격리·권한 양방향 확인. 실패면 이후 명령 거부
bench run     --model X --exp review_convergence   raw + profile + prescription 산출
bench compare                               ledger.md 재생성 (모델 × 특성 표)
bench prescribe --model X                   프로파일 → 운용 처방 (근거 등급 병기)
```

- 모델 어댑터: `claude` / `codex` 를 참조 구현으로. 새 모델은 어댑터 하나 추가.
- 모델 어댑터 최소 계약을 확정하고 ADR 로 남긴다 (열린 질문 §5)
- **종료 조건**: claude·codex 로 `bench run` 완주, ledger 2행 + **처방 2건이 생성됨**.
  그 처방이 원 연구가 손으로 내린 결론(claude=팬아웃 필요 / codex=단독 충분)과 일치해야 한다

## 4. 비범위 (명시)

- 모델 순위표(leaderboard). 이건 **하네스 설계의 효과**를 재는 것이지 모델 능력 순위가 아니다.
- 사람 판정이 필요한 지표. tier-1 은 판정 없이 성립해야 한다.
- SpotOn 제품 코드의 유지보수.
- **범용 에이전트 프레임워크.** 코어는 이 레포의 실험들을 위한 것이지 남의 파이프라인을
  위한 것이 아니다. 추상화는 두 번째 실험이 요구할 때 넓힌다 (ADR-001b).
