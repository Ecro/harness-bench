# 과제 — tier-1 과 tier-2

## 티어를 나눈 이유

```
tier-1 (bench)         pytest 만. 의존성 0. 판정 불필요.   ← 모델 비교의 유일한 근거
tier-2 (case-studies)  툴체인 필요. 사람 판정 포함.        ← 기록이지 재현 요구가 아니다
```

안 나누면 남이 툴체인을 못 깔아서 **벤치 전체를 포기한다.** 그리고 tier-2 의 숫자는
판정자 문제(`LIMITS.md` §2)를 안고 있어 모델 비교에 쓸 수 없다.

## tier-1

### `retry_policy` — 촘촘한 계약

지수 백오프 + full jitter + 서킷 브레이커. **19개 인수 조건**, 참조 구현 128줄.

```
오라클 검증
  참조 통과              23/23
  import 실패 시 바닥     0 passed
  보증 1개 제거 시 적발   3개 실패 — 스위트가 확실히 잡는다
```

**계약이 뮤테이션 지점 120개 중 104개(87%)를 고정한다.** 자유 영역은 1개뿐이고,
원 연구의 47라운드 루프가 움직인 관측 동작도 정확히 그 1개였다 — 1:1 일치.

### `ttl_cache` — 성긴 계약, 참조 없음

TTL + LRU 캐시. **8개 인수 조건뿐.** 참조 구현을 **일부러 넣지 않았다** — 이 과제의
질문은 *"계약이 침묵하는 자리에서 모델이 무엇을 고르는가"* 이기 때문이다.

원 연구 결과: 독립 4구현(claude 3 + codex 1)이 **차등 테스트 0/400 으로 완전히 같았다.**
크기는 54줄 vs 138줄로 2.5배 차이인데도 동작이 동일했다. 다만 **관례가 약한 자리**
(타입 오류 처리)에서는 4구현이 3가지 답으로 갈렸다.

> 진동은 계약의 성김이 만드는 것이 아니다. **관례의 부재**가 만든다.

## 새 과제를 추가하려면

`Task(slug, module_name, n_ac, has_reference)` 하나와 디렉터리 셋:

```
tasks/<slug>/SPEC.md              사람이 읽는 계약
tasks/<slug>/test_acceptance.py   동결 인수 스위트 = 오라클
tasks/<slug>/reference.py         (선택) 알려진 정답
```

**그리고 `oracle.verify()` 를 통과해야 한다.** 통과 전에는 그 과제에서 나온 어떤 수치도
인용하면 안 된다 — 원 연구 1부가 이 검증을 건너뛰었다가 무너졌다.

## tier-2 (Phase 5)

C 펌웨어 모듈(`swing_capture.c`, 359줄)과 그 판정 시트. Zephyr/west 툴체인이 필요하고,
진짜/오탐 판정이 **저자 본인**의 것이다. 공개하는 이유는 그래야 원 연구의 오탐 분석을
**누구든 반박할 수 있기** 때문이다.
