# 측정 방법 — 각 숫자를 어떻게 얻었고, 계측기를 어떻게 검증했는가

[English](METHODS.md)

여기 나오는 모든 계측기는 쓰이기 전에 검증된다. 재려는 대상에 반응한다는 것과 그 밖에는
침묵한다는 것이 확인되지 않은 장치는 증거가 아니라 숫자를 만든다.

```
    대상                  격리                 계측기                검증
  ──────────────────────────────────────────────────────────────────────────────────
  동결 소스        →   bwrap 네임스페이스  →   모델 호출        →   양방향 카나리
  지적             →   provenance-blind  →   클러스터링        →   ARI 게이트 + 교차벤더
  후보 코드        →   임시 디렉터리      →   인수 스위트       →   3중 오라클 검증
  두 판본          →   시드 시나리오      →   차등 재생         →   심어둔 발산
  한 판본          →   AST 섭동          →   뮤테이션 테스트    →   스위트가 죽여야 한다
  N회 실행         →   전수 부분집합      →   커버리지 곡선     →   퇴화 사례 검사
  관측된 효과      →   서로소 삼중쌍      →   귀무분포          →   1680쌍 전수
```

---

## 1. 격리 — 지탱하는 불변식은 부정형이다

각 호출은 `bwrap --unshare-all` 네임스페이스 안의 새 프로세스 하나다. 불변식은 부재로
서술된다 — **대상 리포지토리를 네임스페이스에 절대 바인드하지 않는다.** 그래서 명세든
정답지든 이전 지적이든, 절대경로 읽기가 애초에 resolve 되지 않는다. CLI 가 도구 제한
플래그를 지키든 말든 무관하게.

플래그는 경계가 아니기 때문이다. 어떤 CLI 의 `-s read-only` 는 읽기를 **허용하는** 셸 실행
정책이고 도구 스위치가 아예 없다. 그 CLI 만 샌드박싱하면 읽기 능력이 모델 간에 비대칭이
되어 모델 정체성과 교란되므로, 네임스페이스는 양쪽에 똑같이 적용한다.

프롬프트는 argv 가 아니라 **stdin** 으로 전달한다. 따옴표·백틱·`$` 를 담은 큰 입력은
망가지거나 ARG_MAX 를 넘고, **조용히 손상된 입력은 여기서 가능한 최악의 실패**다 —
다른 모든 숫자가 그것을 기준으로 측정되기 때문이다.

대상은 고정 오프셋의 **맨 앞**에, 지시는 그 뒤에 놓는다. 어떤 지시가 따라오든 코드가 모든
팔에서 동일한 토큰 위치를 차지하도록.

### 검증: 양방향 카나리

*"모델이 정답지를 못 읽었다"* 는 아무것도 증명하지 않는다. 고장난 프로브는 완벽한 격리와
같은 답을 낸다 — 도구 미부착, 프롬프트 미전달, CLI 사망, 권한 프롬프트 자동 거부.

그래서 모든 격리 주장은 **같은 호출 안에서** 두 방향을 함께 든다.

```
POS   도달 가능해야 하고 실제로 되는 대상      (심어둔 마커, 시스템 파일)
NEG   도달 불가여야 하고 실제로 안 되는 대상   (이 레포지토리)
```

어느 한쪽이 없는 `Canary` 는 생성 시점에 예외를 던지고, `require_pass()` 에 우회는 없다.
POS 쪽 실패는 격리가 아니라 **고장난 프로브**로 보고된다.

POS 레그는 **그 어댑터가 실제로 할 수 있는 것**만 요구해야 한다. 읽기 전용 어댑터가 쓰기로
격리를 증명할 수는 없고, 그 실패를 모델 차이로 읽으면 틀린다.

카나리 원본 응답은 항상 저장한다. 실패한 카나리가 곧 증거다.

## 2. 인수 오라클 — 세 방향으로 검증한다

계약이 오라클이다. 명세, 구현이 존재하기 전에 그것에서 파생된 스위트, 그리고 스위트가
만족 가능한지 확인하는 데만 쓰는 참조 구현.

한 번도 돌려보지 않은 스위트는 오라클이 될 수 없다. 매 푸시마다 CI 가 돌리는 세 검사이고,
통과 전에는 그 과제의 어떤 숫자도 인용할 수 없다.

```
참조 통과                  알려진 정답 구현이 초록이다                23/23
import 실패 시 바닥        import 불가 모듈이 0점, "전부 통과" 아님    0 passed
보증 1개 제거 시 적발      가드 절 하나를 지우면 스위트가 알아챈다     3개 실패
```

세 번째가 핵심이다. 보증을 지웠는데도 초록인 스위트는 **그 보증을 재고 있지 않다.**

스위트는 **동결**돼 있다 — 구현 전에 명세만 보고 작성했고 이후 수정하지 않는다. 그 동결이
*"테스트가 구현에 맞춰졌다"* 는 반박을 막는 유일한 장치이며, 주석과 번역까지 포함한다.

## 3. 지적 묶기 — 세 번, 섞어서, 게이트를 걸고

리뷰 10회는 하나의 결함을 열 가지 문장으로 서술한다. 빈도·중복·커버리지는 묶기 전에는 아무
의미가 없고, 묶는 일은 모델이 한다.

두 성질을 강제한다.

**Provenance-blind.** 클러스터러는 불투명한 위치·로케이터·본문만 본다. 어느 모델·회차·팔이
냈는지는 절대 보지 않는다. 그러지 않으면 클러스터 경계가 — 무의식적으로라도 — 한 팔에
유리하게 그어질 수 있고, 이후의 모든 비교가 그것을 물려받는다.

**매 실행 순서를 섞고 시드를 기록한다.** 입력 순서가 같으면 세 실행이 *제시*를 통해
상관되고, 게이트는 클러스터링 안정성이 아니라 **프롬프트 결정성**을 재게 된다 — 잘못된
이유로 통과한다.

세 번 돌려 Adjusted Rand Index 로 비교하고, medoid 를 이후 분할로 쓴다.

### 게이트는 숫자를 내주기를 거부한다

문턱 미달이면 결과는 숫자가 아니라 문자열 `UNQUOTABLE` 이다. **단서를 달고 나간 숫자는 단서
없이 인용된다.**

실제로 물렸다 — 한 팔이 **ARI 0.781** 로 나왔고, 그 팔의 고유 결함 수는 연구 어디에서도
인용되지 않았다.

### 계측기 자체의 교차벤더 검증

한 모델을 세 번 돌려 일치하는 것은 일관성을 증명하지 정확성을 증명하지 않는다 — 체계적
편향을 공유하면 완벽히 일치하면서 함께 틀릴 수 있다. 그래서 같은 61건을 **다른 벤더의
모델**에게 묶게 했고, 같은 14개가 나왔다.

인용된 자리의 실측 일치도: **ARI 1.000**(단일 팔 풀), **0.978**(3팔 128건),
**0.963**(193건).

## 4. 자유 공간 분모 — 주장이 아니라 측정

"루프가 동작 하나를 움직였다" 는 **움직일 수 있었던 자리가 몇 개인지** 모르면 의미가 없다.
조작적 정의:

> **어떤 지점의 섭동을 동결 스위트가 죽이면, 그 지점의 답은 정의돼 있다.**

참조 구현에 대해 한 번에 하나씩 AST 를 섭동하고, 각 뮤턴트를 동결 스위트로 돌린다.

```
뮤테이션 지점 120개
  104  스위트가 죽인다 — 계약이 고정한다              (87%)
   16  생존하고, 손으로 분류한다:
         9  관측상 등가 (차등 테스트로 구별 불가)
         4  스위트 구멍 — 역방향을 검사하지 않는다
         3  진짜 자유, 하나의 영역을 이룬다
```

스위트 구멍 4개는 모델이 아니라 **오라클에 대한 발견**이다. `if x < 0` 을 `if x < 1` 로
바꿔도 23개 테스트가 전부 통과하면서 유효한 설정을 거부한다 — 조건이 *무엇을 거부해야
하는가* 만 말하고 *무엇을 받아들여야 하는가* 는 검사하지 않기 때문이다.

47 루프 라운드가 움직인 관측 동작은 정확히 하나, 그 단일 자유 영역 안이었다 — 모델이 움직인
자리와 계약이 침묵한 자리가 1:1 로 일치한다.

## 5. 차등 테스트 — 그리고 하네스를 먼저 시험한다

두 판본을 **300개의 시드된 연산 시나리오**로 각각 재생해 관측 트레이스를 비교한다. 대상이
완전히 결정적이기에 가능하다 — 시간·수면·난수를 전부 주입받는다.

하네스 자체를 신뢰하기 전에 심어둔 변경으로 검증한다.

```
v0 대 v0                          0/300     오탐이 없다
지터를 상한 前에 곱하도록 변경     39/300    진짜 차이는 잡는다
주석만 / 예외 메시지만 변경        0/300     스타일 변경은 안 잡는다
```

두 번째 과제에서는 자유 영역 선택을 일부러 뒤집어 같은 검사를 했다 —
**95/400, 400/400, 369/400**, 전부 잡았다.

발산은 **서명**으로 환원해서, "구별되는 동작 변화가 몇 종인가" 가 인상이 아니라 개수가 되게
한다.

## 6. 우연 기준선 — 추정이 아니라 전수 계산

리뷰 1회가 일부만 보므로, 코드를 안 바꿔도 2차 배치는 "새" 지적을 낸다. 그 기준선 없이
신규율을 인용하면 수정이 아니라 표집을 재는 것이다.

귀무분포는 코드 무변경 상태의 기존 리뷰 9회 안에서 **서로소 삼중쌍 1680개를 전수 열거**해
만들었다 — 추가 모델 호출 0.

```
귀무 (코드 무변경)     중앙값 11%, 범위 0~31%
병합 수정 이후          77% / 89% / 63%      귀무분포의 100분위
```

## 7. 예산 곡선 — 이미 값을 치른 부분집합에 대한 전수 계산

N 회의 독립 실행이 있으면 "k 콜이면 얼마나 찾았을까" 는 추정이 아니다. 모든 C(N,k) 부분집합의
평균이고, 추가 비용이 들지 않는다.

구현은 쓰기 전에 퇴화 사례로 검사한다 — 모든 실행이 같은 집합을 찾는 풀은 상수를 내야 하고,
서로소인 풀은 선형으로 늘어야 한다.

혼합 곡선은 k 를 두 팔에 나누는 모든 분할을 열거해 최선을 보고하고, 그것을 낸 분할을 함께
적는다.

## 8. 복잡도 — 익숙함이 아니라 근거로 고른 대리변수

순환복잡도는 **일부러 뺐다.** LOC 와의 상관이 r ≈ 0.85~0.87 이라 크기 위에 얹는 정보가 거의
없다. 이 데이터에서 실측하니 r = 0.807 이었다.

대신 Cognitive Complexity 를 썼다. *이해 시간*과의 상관이 실증적으로 측정됐기 때문이다.
그래도 대리변수이고, 대리변수로 보고한다.

절대 단독으로 보고하지 않는다 — 줄 수, 누적 churn, 생존 뮤턴트 수, 인수 스위트 준수율을
함께 낸다. 준수율은 10개 팔 47라운드가 전부 동일했고, **그 자체가 발견이다** — 모두가 먼저
집는 지표가 아무것도 판별하지 못한다.

생존 뮤턴트는 비율보다 **절대 수**를 쓴다. 비율은 모든 팔에서 0.83~0.90 으로 움직여 아무
주장도 지지하지 못했고, 절대 수는 한 팔을 깨끗이 갈랐다(16 → 24).

## 9. 프롬프트 변형 — 스크립트로 파생하고 diff 로 확인한다

카테고리 프롬프트 여섯을 손으로 쓰면 어휘·강조·출력 규칙이 흔들리고, 그 흔들림이 그대로
그 팔의 효과로 읽힌다. 변형은 원본에서 스크립트로 파생하고, diff 가 **정확히 한 축만**
바뀌었음을 보여야 한다.

바이트 그대로 두는 것들 — 각각이 교란이 되기 때문:

- 출력 스키마와 호출당 지적 상한
- 허용 문구 *"빈 결과도 유효한 답이다"* — 이걸 지우면 전문 리뷰어에게 자기 영역에서
  **뭐라도** 말하라는 압력이 걸리고, 그 팔의 늘어난 지적 수는 측정이 아니라 프롬프트의
  산물이 된다
- 특정 행을 지목하라는 지시

파생 스크립트가 한 블록만 바뀌었는지 스스로 검사하고, 모든 결과에 프롬프트 SHA-256 이
기록된다.

## 10. 판정 — 눈을 가리고, 내부 통제군과 함께

*"이 지적이 진짜인가"* 에 판단이 필요한 자리에서는 절차를 미리 고정한다.

- 배타 지적을 **양쪽 팔이 모두 낸 지적과 섞고** 순서를 섞어, 판정자가 어느 팔의 것인지
  알 수 없게 한다
- 공통 집합이 내부 통제군 역할을 한다 — 배타 집합이 더 낫지 않으면 그것과 대비돼 드러난다
- 정답 키는 별도 파일에 쓰고, 판정이 기록되기 전에는 열지 않는다

판정은 이 작업에서 가장 약한 고리로 남아 있고, 그 숫자가 나오는 모든 자리에 그렇게 표시된다
— 판정자가 연구의 저자였다. tier-1 과제가 존재하는 이유가 바로 이것이다: 판정이 아예
필요 없다.

## 11. 사전등록과 재시도 금지

예측은 데이터 전에 동결되고 해시가 찍히며, 반증 조건이 없으면 생성 시점에 거부된다. 동결
파일을 편집하면 로드에 실패한다. 사전등록 없는 실행은 결과와 원장에 `exploratory: true`
낙인이 찍힌다.

이 연구에서 동결한 다섯 예측 중 **둘이 실패했고**, 그 두 실패가 성공한 셋보다 유익했다.
사후 서술이었다면 어느 쪽도 살아남지 못했을 것이다.

**어떤 호출도 재시도하지 않는다.** retry 파라미터가 없고 테스트가 그 부재를 강제한다.
응답이 잘 나올 때까지 다시 부르면 잘 행동한 표본만 남고, 그것이 바로 측정 대상인 변동폭을
편향시킨다. 실패·파싱 불가 호출은 기록하고 보존하며, 그것이 루프를 일찍 끝냈으면 다시
시작하지 않고 **일찍 끝났다고 보고한다.**

## 계측기가 거부하는 것들

| 상황 | 나오는 것 |
|---|---|
| 클러스터링이 재현되지 않음 | `UNQUOTABLE`. 각주 달린 숫자가 아니다 |
| 루프가 3개 미만 | `None`. 둘의 다수결이 아니다 |
| 계열이 4점 미만 | 그 루프에 대한 비율 없음 |
| CLI 가 사용량을 안 줌 | `degraded`. 조용한 0 이 아니다 |
| 카나리 POS 레그 실패 | 예외. 실행이 진행되지 않는다 |
| 처방 규칙에 근거 등급이 없음 | 렌더되지 않는다 |

각각은 숫자를 낼 수 있었고, 냈다면 틀렸을 자리다.
