# 알려진 불일치 — 원 연구와 이 레포의 측정이 갈리는 지점

지우지 않고 적는다. 이 레포의 값어치는 숫자가 아니라 **숫자가 언제 안 맞는지를 아는 것**이다.

---

## D-001 — claude 의 churn 방향 [해소됨 2026-08-21]

**결론: 원 연구가 맞았고, 이 레포의 첫 측정이 이상치였다. 그리고 내가 원 연구와
정확히 같은 실수를 반대 방향으로 저질렀다.**

### 무슨 일이었나

원 연구는 claude 를 *"churn 이 마르지 않는다"* 로 기록하고 그 위에 ★★★ 처방 둘을
세웠다 — *"라운드 상한 필수"*, *"churn 을 정지 기준으로 쓰지 마라"*. **루프 하나에서
나온 방향이었다.**

이 레포의 첫 측정은 반대로 나왔고(ratio 0.617, "마름"), 나는 그것을 반증으로 적었다.
**그것도 루프 하나였다.**

### 3루프로 갈랐다

```
L1  [90, 100, 107,  65, 51]   ratio 0.611   마름
L2  [101, 82, 101, 101, 33]   ratio 0.732   안 마름
L3  [106, 69,  82,  51, 75]   ratio 0.720   안 마름
──────────────────────────────────────────────────
판정  churn_dries = False       갈림 1:2
```

세 비율이 **0.611~0.732 로 문턱 0.7 언저리에 몰려 있다.** 루프 하나만 뽑으면 어느
쪽으로든 나온다 — 첫 측정의 0.617 은 그 분포의 아래쪽 꼬리였다.

### 남는 것

- **원 연구의 방향은 유지된다** (claude 의 churn 은 마르지 않는다).
- **그러나 등급은 ★★★ 를 유지할 수 없다.** 두 가지 이유:
  1. 판정이 **갈림 1:2** 다. 만장일치가 아니다.
  2. codex 는 `None` 이다(D-002) — 이 특성은 **두 모델에서 재현될 수 없고**,
     따라서 ★★★("두 모델 이상에서 재현")의 정의를 만족할 방법이 구조적으로 없다.
  → `churn_gate` / `round_cap` 규칙의 등급을 **★★ 로 내린다.**
- **문턱 0.7 이 이 과제에서는 분포 한복판에 있다.** 이분법이 아니라 `churn_ratio`
  연속값을 같이 읽어야 한다. 그래서 특성으로 노출해 뒀다.

### 교훈 (이 레포가 존재하는 이유)

> 원 연구는 n=1 에서 "안 마름" 을 뽑아 ★★★ 를 달았고, 나는 n=1 에서 "마름" 을 뽑아
> 그것을 반증이라 불렀다. **둘 다 표본을 방향으로 착각했다.**
> `_dries_across()` 가 3루프 미만을 판정 불가로 두는 이유가 이것이고, 그 함수는
> 이 사고 뒤에 쓰였다.

## D-002 — codex 는 이 지표를 측정당할 만큼 오래 돌지 않는다 [재분류]

3루프를 돌린 뒤에도 판정 불가다.

```
L1  [54, 13]                2점 -- 4점 미만이라 비율 계산 불가
L2  [22, 20, 3, 15, 5]      ratio 0.476   마름
L3  [49, 18, 18, 3]         ratio 0.313   마름
──────────────────────────────────────────────
판정  churn_dries = None    "루프 2/3 -- 판정 불가"
```

판정 가능한 두 루프가 **둘 다 강하게 "마름"** 인데도 `None` 이다. `MIN_LOOPS=3` 때문이다.
문턱을 낮추면 답이 나오지만 **낮추지 않는다** — 그 규칙이 존재하는 이유가 D-001 이고,
답을 얻고 싶어서 문턱을 내리면 같은 실수를 반복한다. `churn_ratio` 에 루프별 값이
전부 보이므로 읽는 사람이 판단할 수 있다.

**재분류**: 이것은 "codex 가 빨리 마른다" 가 아니라 **"codex 는 너무 빨리 끝나서
마르는지 잴 수 없다"** 이다. L1 은 2라운드, L3 은 4라운드에 지적 0 으로 종료했다.
서술이 다르고, 후자가 정확하다.

**해소 조건**: 지적이 0 이어도 라운드를 계속 돌리는 옵션을 만들거나, 더 큰 과제를 쓴다.
전자는 조건을 바꾸는 것이라 신중해야 한다.

## D-003 — tier-1 은 두 특성을 원리적으로 못 잰다

`finds_per_call` 과 `verbosity_shift` 는 tier-2 전용이다(`docs/TASKS.md`).
따라서 원 연구의 가장 강한 결과 중 하나 — *"리포 접근이 오탐을 없앤다, 두 모델에서 재현"* —
은 **이 벤치의 tier-1 실행으로는 재확인되지 않는다.**

불일치는 아니지만, 원장을 읽는 사람이 *"이 표에 그게 없네"* 라고 물을 자리라 적어둔다.
