# 설계

[English](DESIGN.md)

`harness-bench` 는 **하네스 설계**를 측정한다. 모델 능력이 아니다. 하네스란 모델을 감싸는
루프, 프롬프트, 도구 접근 권한, 정지 조건을 말한다. 답하려는 질문은 실용적이다 —
*이 모델이 주어졌을 때, 그 주위의 루프를 어떻게 구성해야 하는가?*

이 문서는 그 구조와, 코드가 강제하는 여섯 규율의 이유를 적는다.

---

## 1. 두 층, 하나의 경계

```text
harness_bench/
  core/                     "어떻게 재는가" 를 알고 "무엇을 재는가" 는 모른다
    sandbox/    파일시스템 격리 + 양방향 카나리 프레임워크
    runner/     모델 어댑터 · 재시도 없는 호출 · 토큰 회계
    cluster/    provenance-blind 묶기 + ARI 안정성 게이트
    prereg/     예측 동결 · exploratory 낙인
    stats/      전수 조합 커버리지 · 뮤테이션 · 차등 재생 · 복잡도
    ledger/     결과 저장 · 모델 프로파일 · 처방 렌더
  experiments/
    review_convergence/     과제 · 프롬프트 · 오라클 · 지표 · 특성
```

**경계 규칙**: `core` 는 `experiments` 를 import 할 수 없고, 도메인 어휘를 코드에 담을 수도
없다. `tests/test_core_boundary.py` 가 둘 다 강제한다.

실험이 코어에 제공하는 것은 정확히 다섯 개다 — **과제 · 프롬프트 · 오라클 · 지표 ·
사전등록**. 여기서 오라클은 어떤 결과가 옳은지 그른지를 판정하는 기준을 뜻하고, 사전등록은
데이터를 보기 전에 예측을 동결해 두는 절차를 뜻한다.

그 밖의 것이 필요하다면 코어가 부족한 것이지 경계를 굽힐 자리가 아니다. 경계는 지금, 실험이
하나뿐일 때 고정한다. **측정 조건이 움직이는 벤치마크는 벤치마크가 아니기 때문이다.**

## 2. 산출물은 점수가 아니라 프로파일과 처방이다

점수는 모델을 줄 세운다. **프로파일**은 지금 가진 모델을 어떻게 운용할지 알려준다.
프로파일은 측정된 특성의 모음이고, 처방은 그 특성을 하네스 설정으로 옮긴 것이다.

```text
측정된 특성                              →  결정되는 손잡이
────────────────────────────────────────────────────────────
spread          실행 간 변동폭            →  리뷰를 몇 번 돌릴 것인가
loop_decay      지적이 줄어드는가          →  라운드 상한이 필요한가
churn_dries     churn 이 수렴하는가        →  churn 을 정지 기준으로 쓸 수 있는가
rejection_rate  수정자로 썼을 때           →  계약 문서를 같이 줘야 하는가
loc_direction   코드를 늘리는가 줄이는가    →  루프를 얼마나 오래 돌려도 되는가
malformed_rate  JSON 준수                 →  구조화 출력을 믿을 수 있는가
tools_blockable 도구를 끌 수 있는가        →  애초에 비교 가능한가
```

`spread` 는 같은 코드를 여러 번 리뷰했을 때 지적 수가 얼마나 흔들리는가, `churn` 은 한
라운드에서 추가·삭제된 줄 수, `rejection_rate` 는 수정자가 근거를 밝히고 고치지 않기로 한
지적의 비율, `malformed_rate` 는 구조화 출력을 지시했는데도 파싱되지 않은 응답의 비율이다.

매핑 규칙은 실험이 소유하고(`traits.py`), 코어는 스키마와 렌더러를 소유한다. 다음 실험은
다른 손잡이를 들고 온다.

**근거 등급은 필수다.** 모든 규칙이 `***`(두 모델 이상에서 재현), `**`(단일 측정),
`*`(판단) 중 하나를 단다. 등급 없는 규칙은 렌더되지 않는다 — 등급이 없으면 의견이 조언으로
세탁되기 때문이다.

## 3. 여섯 규율, 코드로 강제

각각이 런타임 게이트다. 위반은 경고가 아니라 거부를 낳는다.

### 양방향 카나리

카나리는 재기 전에 계측 장치가 실제로 붙어 있는지 확인하는 프로브다.

*"모델이 정답지를 못 읽었다"* 는 그 자체로 아무것도 증명하지 않는다. 고장난 프로브는 완벽한
격리와 **똑같은 답**을 반환하기 때문이다 — 도구 미부착, 프롬프트 미전달, CLI 사망, 권한
프롬프트 자동 거부가 전부 "읽지 못했다"로 보인다.

그래서 모든 격리 주장은 **같은 호출 안에서** 두 레그를 함께 든다. 도달 가능해야 하는 **POS**
대상과 도달 불가여야 하는 **NEG** 대상이다. 둘 중 하나가 없는 `Canary` 는 생성 시점에 예외를
던지고, `require_pass()` 에는 우회 플래그가 없다. POS 쪽 실패는 격리가 아니라 **고장난
프로브**로 보고된다.

카나리는 또한 **그 어댑터가 실제로 할 수 있는 것만** 프로브해야 한다. 읽기 전용 어댑터에게
쓰기로 격리를 증명하라고 요구할 수는 없다.

### 재시도 금지

`call()` 에는 retry 파라미터가 없고, 테스트가 그 부재를 강제한다. 응답이 잘 나올 때까지 다시
부르면 **잘 행동한 표본만 남는데**, 바로 그 변동폭이 측정 대상이다.

실패하거나 파싱되지 않은 호출은 기록되어 그대로 반환된다. 표본이 더 필요하면 **독립적인
호출**을 하고 그것을 독립적인 관측으로 기록한다.

### ARI 게이트

빈도·중복·커버리지 같은 값은 같은 결함을 가리키는 지적을 하나로 묶은 뒤에야 의미를 갖고,
묶는 일은 모델이 한다. 그래서 세 번 돌리고, 매 실행 순서를 섞으며(시드를 기록한다), 세 분할을
Adjusted Rand Index(ARI)로 비교한다. ARI 는 두 분할의 일치도를 재는 값으로 1.0 이면 완전히
같다.

문턱 미달이면 결과는 숫자가 아니라 문자열 `UNQUOTABLE` 이다. **단서를 달고 나간 숫자는 단서
없이 인용되기 때문이다.**

순서를 섞는 것이 중요하다. 입력 순서가 같으면 세 실행이 *제시 순서*를 통해 상관되고, 게이트는
클러스터링 안정성이 아니라 **프롬프트의 결정성**을 재게 된다.

### 사전등록

반증 조건 — 어떤 결과가 나오면 이 예측이 틀린 것인지 — 이 없는 예측은 예측이 아니라 서술이며,
생성 시점에 거부된다. 동결된 파일에는 해시가 찍히고, 사후에 편집하면 로드가 실패한다.

사전등록 없는 실행은 금지가 아니라 **낙인**이다. `exploratory: true` 가 결과와 원장까지
따라붙는다.

### 프롬프트 기계 파생

프롬프트 변형은 원본에서 스크립트로 파생하고, diff 가 **정확히 한 축만** 바뀌었음을 보여야
한다. 출력 스키마·호출당 상한·*"빈 결과도 유효한 답이다"* 같은 허용 문구는 바이트 그대로
둔다.

마지막 문구 하나를 지우면 전문 리뷰어에게 자기 영역에서 뭐라도 말하라는 압력이 걸리고, 그
팔의 늘어난 지적 수는 측정 결과가 아니라 **프롬프트의 산물**이 된다. 모든 결과에 프롬프트의
SHA-256 해시가 기록된다.

### 귀속 전에 환경 검증

모델의 행동과 하네스의 설정은 밖에서 보면 구별되지 않는다. 어떤 차이를 모델의 특성으로
기록하기 전에 설정을 양방향으로 확인한다.

구체적으로는 이렇다. 스크래치 루트가 `/tmp` 아래면 거부한다(어떤 CLI 는 거기에 샌드박스
헬퍼를 만들기를 거부하고, 그 실패는 모델이 능력을 안 쓴 것과 똑같이 보인다). 요청한 별칭이
아니라 **해석된 모델 id** 를 기록한다. 그리고 어댑터는 애초에 도구를 끌 수 있는지를 스스로
선언한다.

## 4. 재현 게이트

이식이나 리팩터링의 진짜 위험은 크래시가 아니라 **조용한 드리프트**다 — 코드는 돌고, 숫자는
그럴듯하고, 아무도 이전 값과 대조하지 않는다.

그래서 저장된 산출물을 새 코드로 다시 분석해 이전 값과 대조하되, **모델을 부르지 않는다.**
모델을 부르는 재현 게이트는 재현이 아니라 새 실험이다.

## 5. 시크릿

러너는 CLI 가 인증할 수 있도록 실제 자격증명을 스크래치 HOME 으로 복사한다. 그 디렉터리가
한 번이라도 커밋되면 되돌릴 수 없으므로 세 겹으로 막는다 — `.gitignore`, `pre-commit` 훅,
그리고 CI. 셋이 `tools/secret_scan.sh` 를 공유해 패턴이 서로 갈라지지 않게 한다.

스캐너는 매 실행 전에 심어둔 토큰으로 자기검증을 한다. *"찾은 게 없다"* 는 고장난 스캐너도
똑같이 내는 출력이기 때문이다.
