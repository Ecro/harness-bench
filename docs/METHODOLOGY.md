# 방법론 — 규율 여섯 개와, 각각을 만든 실패

이 레포의 실질은 도구가 아니라 규율이다. 도구는 규율이 잊히지 않게 하는 장치다.

원 연구는 400여 회의 LLM 호출로 11개 실험을 돌렸고 **결론이 스무 번 뒤집혔다.**
방향은 항상 덜 극적인 쪽이었고, 상당수는 코드가 아니라 **측정 조건**이 만든 것이었다.

아래 여섯 개는 전부 *실제로 일어난 사고*에서 나왔다. 각 절은 이렇게 읽으면 된다 —
**무엇이 잘못됐는가 → 왜 안 보였는가 → 코드가 지금 무엇을 거부하는가.**

---

## 1. 양방향 카나리 — "안 읽혔다"는 증명이 아니다

**사고.** 리뷰어가 정답지를 못 읽는 것을 확인하려고 물었다. *"이 파일 읽어봐."* → *"못 읽겠다."*
격리 성공으로 기록했다.

**왜 안 보였는가.** 그 답은 두 경우에 똑같이 나온다.

```
① 격리가 잘 됐다              ← 원한 것
② 프로브가 고장났다            ← 구별 불가
   도구 미부착 · 프롬프트 미전달 · CLI 사망 · 권한 프롬프트 자동 거부
```

실제로 codex 가 **양쪽 다 NOT-READABLE** 을 반환한 적이 있다. NEG 만 봤다면
*"codex 는 리포를 줘도 안 읽는다"* 는 **모델 특성**으로 기록됐을 것이다. 실제로는
스크래치 디렉터리 위치 문제였다(§6).

**코드가 거부하는 것.** `Canary` 는 POS 레그나 NEG 레그가 없으면 **생성 자체가 실패**한다.

```python
Canary(prompt, [Leg("key_blocked", "NEG", ...)])
# ValueError: a canary with no POS leg cannot distinguish
#             isolation from a broken probe
```

`require_pass()` 에는 우회 플래그가 없다. POS 가 실패하면 예외 메시지가
*"A FAILED POS LEG IS A BROKEN PROBE, NOT ISOLATION. Any data collected now is void."*
라고 말한다.

---

## 2. 재시도 금지 — 재시도는 잘 나온 표본을 고른다

**사고.** 응답이 JSON 이 아니면 다시 부르고 싶어진다. 한 번만 더 하면 되니까.

**왜 안 보였는가.** 이 실험들이 재는 것 중 하나가 **변동폭**이다. 파싱 실패한 호출을
성공할 때까지 다시 부르면 **잘 행동한 표본만 남는다.** 변동폭은 실제보다 작게 나오고,
malformed 율은 0 에 가까워진다 — 둘 다 보고되는 수치다.

원 연구는 이 원칙 때문에 몇 번 손해를 봤다. E10 에서 한 루프가 2라운드에서 죽어
실질 관측이 1.25 루프가 됐고, 그대로 적었다. 늘리지 않았다.

**코드가 거부하는 것.** `call()` 에 **retry 파라미터가 없다.** 테스트가 부재를 강제한다.

```python
def test_runner_has_no_retry_parameter():
    assert not any("retry" in p or "attempt" in p for p in params)
```

재시도가 필요하다고 느끼면, 필요한 것은 **독립적인 두 번째 호출**이고 그렇게 기록해야 한다.

---

## 3. ARI 게이트 — 단서 붙은 숫자는 단서 없이 인용된다

**사고.** 지적들을 고유 결함으로 묶어야 빈도·중복·커버리지가 의미를 갖는다. 묶는 일은
LLM 이 한다. 그런데 **그 묶음이 안정적인지** 확인 안 하면 그 위의 모든 수치가 모래 위다.

**왜 안 보였는가.** 원 연구에서 codex 대조군이 ARI 0.781 로 나왔다. 세 번 묶었는데 서로
많이 달랐다는 뜻이다. 이 경우 *"codex 는 고유 결함 N개를 찾았다"* 는 **말할 수 없다.**
그런데 표에 숫자를 넣고 각주로 "ARI 낮음" 을 달면, 표는 인용되고 각주는 안 따라간다.

**코드가 거부하는 것.** 게이트 미달이면 **숫자가 아니라 문자열** `UNQUOTABLE` 이 나온다.

```python
ClusterResult(..., mean_ari=0.781, gate_pass=False).quotable()  # -> "UNQUOTABLE"
ClusterResult(..., mean_ari=0.978, gate_pass=True ).quotable()  # -> 19
```

**클러스터러는 provenance-blind 이고 매 실행 순서를 섞는다(시드 기록).** 순서가 같으면
세 실행이 *제시 순서*를 통해 상관되고, 게이트는 클러스터링 안정성이 아니라 **프롬프트
결정성**을 재게 된다 — 잘못된 이유로 통과한다.

---

## 4. 사전등록 — 예측이 빗나가야 정보가 된다

**사고.** 결과를 보고 나면 언제나 설명이 생긴다. 그 방향이 처음부터 예상됐던 이유가.

**왜 안 보였는가.** 원 연구는 예측을 다섯 번 동결했고 **두 개가 실패했다.**
그리고 그 둘이 성공한 셋보다 유익했다.

```
P5  "팬아웃이 동일 예산에서도 우세"    →  43% vs 50%.  이득은 구조가 아니라 예산이었다
P1  "범위만 주면 두 팔 사이"          →  위로 튀었다.  확인할 문서 없이 "고정" 만 들으면
                                        애매한 것을 전부 거절한다
```

둘 다 사후 서술이었다면 살아남지 못했을 것이다.

**코드가 거부하는 것.**
- 반증 조건 없는 예측은 **생성 거부** — *"설명이지 예측이 아니다."*
- `freeze()` 후 편집하면 `load()` 가 **해시 불일치로 거부**한다.
- 사전등록 없는 실행은 금지가 아니라 **낙인**이다. `exploratory: true` 가 결과와
  원장까지 따라가고, 어떤 서식으로도 지워지지 않는다.

---

## 5. 프롬프트 기계 파생 — 한 축만 바꾼다

**사고.** 카테고리별 리뷰어 프롬프트 5개를 손으로 썼다. 첫 시도에서 **두 줄을 빠뜨렸다.**

**왜 안 보였는가.** 손으로 쓰면 어휘·강조·출력 규칙이 미묘하게 달라지고, **그 차이가
그대로 팬아웃 팔의 효과로 오해된다.** 특히 *"빈 배열도 유효한 답"* 문구를 지우면
렌즈마다 "뭐라도 말해라" 는 압력이 걸리고, 그러면 팬아웃의 지적 증가는 측정이 아니라
**프롬프트가 만든 것**이 된다.

**규율.** 프롬프트는 원본에서 **스크립트로 파생**하고, `diff` 로 변경이 한 축뿐임을
확인한다. 15건 상한·빈배열 허용·스키마·출력 규칙은 **바이트 그대로** 유지한다.
결과에는 프롬프트 SHA-256 이 박힌다.

## 6. 조건을 모델 특성으로 오귀속하지 마라 — 세 번 그랬다

이건 별도 규율이라기보다 **위 다섯 개가 왜 필요한지**에 대한 답이다.

```
① "codex 는 도구를 못 막는다 → 능력 비대칭"    실제로는 codex 셸이 고장나 있었다
② "codex-linux-sandbox 부재 = 설치 결함"       실제로는 스크래치가 /tmp 라서
③ ②의 정정 자체도 절반만 맞았다
```

②가 특히 좋은 예다. codex 는 그 헬퍼를 **패키지로 배포하지 않고 실행 시점에
`CODEX_HOME` 아래에 만든다.** 그리고 임시 디렉터리 아래에는 만들기를 **거부한다**:

```
WARNING: Refusing to create helper binaries under temporary dir "/tmp"
```

경고만 남기고 진행한 뒤, 셸 명령에서 `bwrap: execvp codex-linux-sandbox: No such file`
로 죽는다. **3주간 "모델은 리포 접근을 못 쓴다" 로 기록돼 있었다.**

**코드가 거부하는 것.** `Config.require()` 가 스크래치 루트가 `/tmp` 아래면 **거부**한다.
설명과 함께.

> **셋 다 "모델의 성질" 로 논문에 들어갈 뻔했고, 매번 POS 레그 하나가 갈랐다.**

---

## 팀에서 쓸 때 — 1분짜리 카나리

연구용 장치는 필요 없다. 월 1회 이것만 하면 된다.

> 리뷰어에게 *"방금 본 파일 말고 **그 호출자 파일의 N행**을 그대로 인용해봐"* 라고 시켜라.
> 못 하면 권한이 안 붙은 것이다.

*"설정이 안 붙었다"* 와 *"모델이 원래 그렇다"* 는 밖에서 보면 똑같이 생겼다.

---

## 마지막으로 — 이 문서를 안 읽고 포크했다면

이 레포의 숫자는 규율과 함께여야 의미가 있다. 카나리를 빼고, 재시도를 넣고, ARI 게이트를
낮추면 **더 깔끔한 숫자가 나온다.** 그 숫자는 틀렸다.

`docs/LIMITS.md` 를 같이 읽어라. 무엇을 이 벤치로 주장하면 안 되는지가 거기 있다.
